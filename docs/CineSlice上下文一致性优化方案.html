3. P0 核心实现（3-5天）

P0-1：项目记忆系统 P0
借鉴 ManjuForge 三文件思路 | 新增3张表 + 1个服务 | 预计1.5天

数据模型（新增3张表）

表名字段说明
project_bible id, project_id, type(character/world/story), content, version, updated_at 项目级记忆，type区分三类
story_foreshadow id, project_id, description, introduced_episode, status(open/resolved), resolved_episode 伏笔追踪表
character_relationship id, project_id, char_a, char_b, relation_type, intensity, description, updated_episode 角色关系图谱

核心服务：ProjectMemoryService

  • 生成前注入：每次生成分镜/视频前，自动读取项目圣经，拼接到系统提示词中
  • 生成后更新：每集完成后，用AI自动更新剧情摘要，识别新伏笔，更新角色关系
  • 角色圣经生成：剧本解析完成后，自动为每个角色生成标准化视觉锚点（100字内）
  • 伏笔自动识别：AI扫描剧本，识别伏笔并入库，后续剧集自动提醒回收
P0-2：视觉记忆库 P0
借鉴 StoryMem | 新增1张表 + 检索服务 | 预计1.5天

数据模型（新增1张表）

表名字段说明
visual_memory id, project_id, episode_id, shot_id, image_path, memory_type(character/scene/prop), related_entity, embedding, created_at 视觉记忆库，所有关键帧自动入库

核心服务：VisualMemoryService

  • 自动入库：每个关键帧生成成功后，自动提取特征并存入视觉记忆库
  • 智能检索：生成新镜时，按角色名/场景名检索相关历史帧，选最相关的3-5张
  • 相似度匹配：用 CLIP 或简单的文本标签匹配，优先选同角色/同场景的近期帧
  • 参考图注入：检索到的历史帧 + 角色资产图，一起作为多参考图输入视频模型
关键改进：现在视频生成只用文字描述角色，改成"文字描述 + 角色资产图 + 历史关键帧"三重参考，一致性直接翻倍。
P0-3：角色锚点标准化 + 提示词6段式重构 P0
借鉴行业通用 + ArcReel | 重构 directorPromptService | 预计1天

角色视觉锚点格式（100字内，逐字复用）

【角色视觉锚点·强制锁定】 角色名：{name} 性别年龄：{gender}，{age} 面部特征：{face_shape}，{eye_color}，{distinctive_marks} 发型发色：{hairstyle}，{hair_color} 服装：{outfit_top}，{outfit_bottom}，{shoes} 配饰：{accessories} 体型：{body_type}，{height}

6段式提示词结构

①【角色视觉一致性】← 从角色圣经读取，逐字复用，禁止AI修改 ②【场景一致性】← 从场景资产读取，含空间布局+光线+氛围 ③【风格一致性】← 从项目风格预设读取，含画风+色调+画幅 ④【本镜内容】← 动作+情绪+对白+时序分解（导演级v2.0保留） ⑤【首尾帧动作弧】← 前镜尾帧状态→本镜首帧状态→本镜尾帧状态 ⑥【负面提示词】← 一致性专项（变脸/换装/穿模）+ 画质专项

关键改动

  • ①②③段为锁定段，AI优化器不能修改，只能追加④⑤段
  • 角色锚点从 visual_description 升级为结构化字段，生成时自动格式化
  • 每个提示词生成都必须包含①②③段，缺失则警告并自动补全

4. P1 增强实现（3-5天）

P1-1：一致性自检引擎 P1
借鉴行业通用 | 新增服务 | 预计1.5天
  • 生成后检查：每张关键帧/每段视频生成后，用VLM（如Qwen-VL）检查角色一致性
  • 检查维度：面部特征匹配度、服装一致性、场景元素一致性
  • 自动重生成：匹配度低于阈值（如70%），自动调整提示词并重生成（最多3次）
  • 质量报告：每集生成后输出一致性评分报告，标记低质量镜头
P1-2：镜头就绪状态系统 P1
借鉴 instant-drama-magician | 前端+后端 | 预计1天
状态含义用户操作
missing_ref缺少角色参考图先生成角色资产
need_previous前镜未生成，无法保证衔接按顺序生成
stale参考图已更新，需重新生成一键刷新
ready所有参考就绪，可以生成开始生成
P1-3：首尾帧衔接强化 P1
借鉴 BigBanana + instant-drama | 修改生成逻辑 | 预计1天
  • 尾帧自动复用：前一镜的尾帧自动作为后一镜的首帧参考图
  • 动作弧描述：提示词中明确"首帧状态→尾帧状态"的动作变化弧
  • 批量生成顺序：强制按镜头顺序生成，不允许跳序（保证首尾帧衔接）
  • 缺失补全：如果前镜缺失，自动先生成前镜再生成当前镜
P1-4：九宫格表情图资产 P1
借鉴漫剧通用 | 角色资产扩展 | 预计1天
  • 角色资产增加"九宫格表情图"：喜/怒/哀/惊/恐/思/平静/冷笑/哭泣
  • 特写镜头自动选用对应表情图作为参考
  • 情绪变化镜头用起始表情+结束表情双参考

5. P2 长期规划（5-7天）

P2-1：多智能体编排 P2
借鉴 ArcReel Subagent 架构 | 架构级改造 | 预计3天

主 Agent 只做决策和调度，大段上下文（小说原文、剧本）交给专门的 Subagent 处理后回传精炼摘要。避免单次调用上下文爆炸，支持更长的小说。

P2-2：角色关系图谱可视化 P2
借鉴 ManjuForge | 前端可视化 | 预计1天

用 ECharts 或 D3.js 展示角色关系网络，随剧情演进自动更新关系状态（亲密度/敌对/陌生），用户可手动调整。

P2-3：AI导演审核 P2
借鉴 ArcReel 导演Agent | 新增服务 | 预计2天

生成后用AI模拟导演视角审核：轴线规则、180度规则、动作衔接、情绪连贯，不合格自动退回修改。

总结

这套方案的核心是不集成任何外部项目代码，而是把 ArcReel、ManjuForge、StoryMem 等项目的核心思路拆解成独立模块，用 CineSlice 现有的技术栈自己实现。

优势：

  • 零协议风险（不用 AGPL 代码）
  • 零技术栈冲突（纯 React + TypeScript + Express + SQLite）
  • 零功能冲突（新增表+新增服务，不改现有逻辑）
  • 可灰度上线（P0→P1→P2 逐步开启）
  • 完全可控（代码都是自己的，出问题好排查）

建议从 P0 三项开始：项目记忆系统 + 视觉记忆库 + 角色锚点标准化。这三项做完，用户最痛的"人物不一样"问题就能解决大半。

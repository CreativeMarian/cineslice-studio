短剧/漫剧提示词优化与上下文一致性

开源项目调研报告 | 2026-10-02 | 调研范围：GitHub 开源项目 + 学术论文 + AI Skill 市场

1. 核心发现

行业共识：短剧/漫剧的上下文一致性不是靠 Prompt 变戏法，而是靠流水线设计。所有优秀项目都遵循同一原则：

资产先行 → 参考图驱动 → 提示词锁定 → 逐镜迭代

🎭 角色资产先行
先生成角色设计图/四视图作为基准，之后所有分镜和视频都以它为参考图输入，而非纯文字描述
📚 长期记忆系统
用角色档案/世界观/剧情摘要三个文件，每集生成前读取、生成后更新，解决"越更越崩"
🔗 首尾帧衔接
前一镜的尾帧作为后一镜的首帧，用图像插值而非纯文生视频，保证镜头间连贯
🧩 多智能体编排
主 Agent 只做决策，大段上下文交给 Subagent 处理后回传精炼摘要，避免上下文爆炸
🔒 提示词锁定段
每个提示词都包含固定的【角色视觉一致性】【场景一致性】【风格一致性】段落，逐字复用
🔄 迭代式生成
不追求端到端一次生成，而是分镜逐镜生成，每镜都基于前镜结果调整，逐步收敛

2. 重点开源项目详解

ArcReel ★ 5.3k Python
GitHub: ArcReel/ArcReel | AGPL-3.0 | 多智能体编排 | 11个供应商 100+模型

核心理念："一致性是设计出来的，不是 Prompt 变戏法"

一致性技术方案

  • 三类资产库：角色、场景、道具，Agent 通读全文后建立，全片持续追踪
  • 角色 DNA：先生成角色设计图作为基准，之后每一张图像和每一段视频都按它来生成
  • 参考图驱动：Nano Banana 2 等支持多参考图的模型，每镜都把角色资产图作为参考输入
  • 线索清单：关键道具、场景元素跨分镜同样以参考图驱动，不走样、不跳戏
  • Subagent 架构：主 Agent 只读项目状态，大段原文交给 Subagent 处理后回传摘要，上下文不爆

生成流水线（6阶段）

上传小说 → 建立资产库 → 分集规划 → 生成剧本JSON → 角色设计与分镜 → 视频合成

可借鉴点：CineSlice 已有资产库和首尾帧，但可以强化"每镜都强制注入角色参考图"的机制，以及"主 Agent + Subagent"的上下文管理模式

ManjuForge 长期记忆 Hermes Skill
解决"越更越崩"问题 | MIT-0 协议免费商用 | 不依赖特定模型

核心创新：不用 RAG，不用向量数据库，用三个文件实现长期记忆

三文件记忆系统

文件作用更新时机
角色档案.md锁定人设、关系、台词风格角色登场/变化时更新
世界观.md锁定时代、规则、势力世界观扩展时更新
剧情摘要.md每集自动更新，记录伏笔和时间线每集生成后自动更新

实测效果（《代码赘婿》6集测试）

  • 记忆跨集连贯性：6集零崩坏
  • 人设一致性：主角始终用数字+逻辑，无能力跳变
  • 伏笔回收率：100%（11个伏笔全部回收或推进）
  • 关系演进：通过空间距离、道具、行为转变自然推进
  • 第三方评估：A+（7项全A以上）

可借鉴点：CineSlice 可以增加"项目记忆系统"，在项目目录下维护 character_bible.md、world_setting.md、story_summary.md，每次生成分镜/视频前注入，生成后自动更新摘要

instant-drama-magician NPM包 连续性
NPM: instant-drama-magician | 即时短剧魔术师

连续性技术方案

  • 角色参考页：独立的 Characters 页面，缺失角色参考时实时警告
  • 尾帧连续性：前一拍的尾帧作为后一拍的首帧，+ 提示词锁定
  • 多参考图润色：可附加前镜 + 角色 + 素材库静止帧
  • 批量补全：自动填充早期缺失的静止帧，避免纯文本镜头被静默生成
  • 状态徽章：显示 stale / need previous / ready 状态
  • 视频队列：静止帧就绪后才排队生成视频，可跳过

可借鉴点：CineSlice 可以增加"角色参考缺失警告"和"镜头就绪状态"（stale/need previous/ready），让用户直观看到哪些镜头因为缺少前镜参考而无法保证一致性

Mangaforge AI Character Bible
Devpost 项目 | 漫剧生成 | 角色一致性系统

Character Bible 系统

持久化的"角色圣经"存储以下信息：

  • 面部特征 (facial traits)
  • 发型 (hairstyles)
  • 服装 (outfits)
  • 个性 (personality)
  • 表情 (expressions)
  • 姿势参考 (pose references)

注入方式

生成流水线将此记忆注入到每个面板生成步骤：

  • LoRA 适配器
  • 参考嵌入 (reference embeddings)
  • IPAdapter 风格图像条件
  • 上下文提示词构建 (contextual prompt construction)
StoryMem 字节跳动+NTU 学术
2024年12月发布 | 多镜头视频叙事 | 视觉记忆系统

核心洞察：将多镜头生成重新表述为迭代过程，而非尝试端到端合成

Memory to Video 方法

  • 每个镜头生成时都访问"视觉记忆库"
  • 记忆库包含之前所有镜头的关键帧和角色外观
  • 新镜头生成后，其结果自动加入记忆库
  • 支持分钟级连贯叙事视频

可借鉴点：CineSlice 可以实现"视觉记忆库"机制——每个镜头生成的关键帧自动加入项目的视觉记忆，后续镜头生成时自动检索相关角色/场景的历史帧作为参考

3. 提示词优化技术汇总

行业通用的提示词结构

所有优秀项目的视频/图像提示词都遵循类似的分层结构：

【角色视觉一致性·强制锁定】
  角色A：28岁中国男性，清晰下颌线，黑色短发，白色衬衫...
  角色B：25岁中国女性，长直发，红色连衣裙...
【场景一致性】
  现代都市公寓，暖黄色灯光，木质地板...
【风格一致性】
  电影级写实，2.35:1宽画幅，浅景深...
【本镜动作描述】
  角色A从门口走入，角色B抬头看他...
【首尾帧动作弧】
  首帧：角色A站在门口 → 尾帧：角色A走到沙发旁
【负面提示词】
  禁止：变脸、换衣服、文字、水印、变形...

角色锚点压缩技术

把最重要的视觉特征压缩成 100字内、可全镜头复用的提示词锚点：

要求：特征必须具体、客观、可视化，禁止"很帅、很美、气质高级"等模糊描述

示例："28岁中国男性，清晰下颌线，窄长脸，黑色短发微卷，左眉有痣，穿深灰色西装，左手戴银色手表"

四视图/九宫格参考图

  • 角色四视图：正面全身 + 侧面 + 背面 + 超大脸部特写，16:9 比例
  • 九宫格表情：同一角色的9种核心表情，用于特写镜头参考
  • 道具拆解图：中心人物全身立绘 + 周围环绕道具/服装/材质特写
  • 场景概念图：多角度场景设定，保证空间一致性

6. 总结

核心结论

短剧/漫剧的上下文一致性，行业已经形成了成熟的方法论：

  1. 资产先行：先生成角色/场景/道具资产，再生成分镜和视频
  2. 参考图驱动：每镜都把资产图作为参考图输入，而非纯文字描述
  3. 记忆系统：用文件或数据库维护角色/世界观/剧情的长期记忆
  4. 首尾帧衔接：前镜尾帧=后镜首帧，用图像插值保证连贯
  5. 提示词锁定：标准化提示词结构，一致性段落逐字复用
  6. 迭代生成：逐镜生成、逐镜调整，而非端到端一次生成

CineSlice Studio 现状：已经具备了资产库、首尾帧、导演级提示词等基础能力，建议优先增强：

  • 项目记忆系统（角色圣经 + 剧情摘要）
  • 视觉记忆库（历史关键帧自动检索复用）
  • 角色参考图强制注入（每镜都带角色资产图）
  • 镜头就绪状态显示（一致性风险可视化）

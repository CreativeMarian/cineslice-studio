P1 重要 需要修复的问题 ✅ 已全部修复

问题 1：测试视频模型连接时消耗真实配额 已修复

位置：server/src/services/aiProxy.ts 第294-306行

问题：testConnection 方法测试视频模型时，会真实调用 adapter.generate() 创建视频任务，这会消耗用户的 API 配额。用户点击"测试连接"可能只是想验证 API Key 是否有效，却意外产生了费用。

修复方案：不再真实创建视频任务，改为发送轻量级 GET 请求到 /v1/models 端点验证：

  • 返回 401/403 → API Key 无效，连接失败
  • 返回 404/405/其他状态 → 端点可达，视为连接成功
  • 网络错误（超时/DNS失败）→ 连接失败

新增辅助函数：getDefaultVideoEndpoint(provider) 支持 10 个视频厂商的默认端点

问题 2：测试图像模型时固定 2048x2048 尺寸 已修复

位置：server/src/services/aiProxy.ts 第289-293行

问题：测试图像模型连接时固定使用 size: '2048x2048'，但并非所有图像模型都支持这个尺寸。

修复方案：新增 getTestImageSize(provider) 函数，根据模型提供商动态选择：

  • 豆包/火山方舟/Seedream → 2048x2048（要求至少 1920x1920）
  • 其他模型 → 1024x1024（大多数模型都支持）

位置：server/src/services/autoPipeline/stages/video.ts 第269行

问题 4：aiProxy 缓存逻辑冗余判断 已修复

位置：server/src/services/aiProxy.ts 第97-110行

问题：缓存命中检查中，外层已经判断了 params.responseFormat === 'json'，但内层又重复判断了一次，逻辑冗余。

修复：移除内层冗余的 else if (params.responseFormat === 'json') 分支，直接执行 JSON 解析校验。

4. 核心模块深度审查

4.1 AI 调用代理 (aiProxy.ts)

  • 统一入口：文本/图像/视频/音频/视觉理解五类调用
  • 重试机制：指数退避，最多3次重试（视频除外，避免重复扣费）
  • 缓存机制：JSON 输出缓存1小时，图片缓存24小时，坏缓存自动清除
  • 成本统计：每次调用记录 token 数/图片数/视频时长/音频字符数
  • 渲染日志：所有 AI 调用记录到 render_logs 表
  • 模型名解析：支持火山方舟接入点 ID 覆盖
  • 视频测试连接消耗真实配额（P1 问题）
  • 图像测试固定 2048x2048（P1 问题）

4.2 全自动流水线 (autoPipeline)

  • 9阶段串行调度：小说→剧集→剧本→角色→场景→分镜→关键帧→视频→音频→导出
  • 并发守卫：同一项目禁止重复启动，防止双份 AI 花费
  • 幂等跳过：已有产出的阶段自动跳过，避免浪费额度
  • 取消支持：用户可随时取消，任务状态正确更新
  • 断点恢复：任务持久化到数据库，支持中断后恢复
  • 视频并发池：动态调整并发数（1-3个），避免 API 限流
  • 首尾帧衔接：下一镜首帧作尾帧，缓解镜头间不连戏问题
  • 导演级提示词：7层优化（时序/动作/表情/心理/环境/连贯/真实）
  • AI 深度优化：非模板化，真正 AI 理解剧本上下文

4.3 视频生成阶段 (video.ts)

  • 首帧转 base64：本地图片自动转换为 data URL 传给 API
  • 尾帧解析：支持显式尾帧和下一镜首帧两种模式
  • 一致性参考图：角色定妆照/场景/道具注入，防漂移
  • 提示词三层叠加：导演级 → AI深度优化 → 风格预设 → 首尾帧动作弧
  • 提示词 Skill：按模型官方公式重构（Kling/Seedance/MiniMax-H3等）
  • 自动重试：最多3次尝试，指数退避（3秒→6秒）
  • 视频质量门：AI 视觉评分，低质量自动重试
  • 进度实时更新：每完成一个镜头更新任务进度

4.4 视频合成 (videoComposer.ts)

  • 简单拼接模式：直接 concat，保留原始音频
  • 带转场模式：xfade 视频淡入淡出 + acrossfade 音频淡入淡出
  • 音频保留：AAC 192kbps / 44100Hz / 立体声
  • 多格式支持：MP4 输出，兼容主流播放器
  • 已修复：之前使用 -an 导致合成后无声音

4.5 数据模型层 (24个 DAO)

  • 统一 ID 生成：generateId('shot') 等前缀式 ID
  • 时间戳自动管理：created_at / updated_at
  • JSON 字段解析：characters_in_shot 支持数组/JSON字符串/逗号分隔三种格式
  • 事务支持：batchCreate 使用数据库事务保证原子性
  • 软删除：部分表支持逻辑删除（需确认）
  • 索引：需检查关键查询字段是否有索引（如 episode_id, user_id）

6. 安全与错误处理

认证与授权

  • 双模式认证：本地模式（local_user）+ 服务端模式（JWT）
  • 白名单路由：/api/auth/mode, /api/auth/login, /api/auth/register 无需认证
  • JWT 校验：无效 token 返回 401
  • API Key 存储：加密存储在 model_registry 表（需确认加密方式）

错误处理

  • 统一错误格式：{ success: false, error: { code, message } }
  • asyncHandler 包装：异步错误自动捕获
  • AI 错误解析：parseAIError 统一解析各厂商错误格式
  • AIError 类：支持 retryable 标记，控制是否重试
  • 错误边界：前端 ErrorBoundary 组件捕获渲染错误
  • 缓存容错：缓存读取/写入失败不影响主流程

输入校验

  • Zod schema 校验：所有 POST/PUT 请求体均有 validateBody 中间件
  • 参数类型校验：provider/modelName 等枚举值校验
  • 文件上传校验：upload 中间件限制文件类型和大小
  • SQL 注入防护：使用参数化查询（prepared statements）
